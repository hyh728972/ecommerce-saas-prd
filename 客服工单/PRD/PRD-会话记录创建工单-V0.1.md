# PRD-会话记录创建工单-V0.1

> **版本**: V0.1 | **日期**: 2026-08-03 | **状态**: 初稿
>
> **原型目录**: `prototype-cs/admin/` (`admin-session-record.html` 入口 / `admin-ticket-create.html` 建单页 session 分支)
>
> **依据**: 《PRD-客服工单-V0.6.md》(本文为其「创建入口」之一,复用其建单页与工单实体)、《PRD-工作台转工单-V0.1.md》(对照:工作台为重交互抽屉,本文为轻入口跳页)
>
> **归档**: 本稿为现行版本;历史版本见 `archive/`。
>
> **核心口径**:
> - **补单语义**:会话记录页是历史会话回顾入口,多数会话已结束;此处「创建工单」= **给历史会话补一张关联工单,会话状态不变**。区别于工作台转工单的"会话继续"——那边会话本就在进行中。
> - **复用建单页(一页多入口)**:不新建页面。行操作跳 `admin-ticket-create.html?mode=session`,带会话上下文;与工单列表(standalone)/订单列表(batch)/订单详情(order)/工作台(抽屉)共用同一建单页。
> - **工单仅客服可见**:工单为内部处理,用户端无感知,建单不给客户发消息(V0.6 §一)。
> - **来源固定**:本入口创建的工单 `source=1`(会话转),不展示来源选择。
> - **落库等价**:与工作台转工单产出等价(均 source=1、`session_id` 关联会话);区别仅在入口形态(跳页 vs 抽屉)与会话语义(补单 vs 转单继续)。

## 总览:会话记录创建工单流程

```mermaid
flowchart LR
    A[会话记录页<br/>选中一条历史会话行] -->|点行操作「创建工单」| B[读行数据拼 URL<br/>跳建单页 ?mode=session]
    B --> C[建单页 session 分支<br/>带入会话+客户上下文]
    C --> D{客服核对 / 补充}
    D -->|选业务类型 / 加订单 / 改联系方式| D
    D -->|「创建工单」提交| E[生成工单 #TK<br/>source=1, session_id=该会话]
    E --> F[工单进入 V0.6 工单列表]
    E -.会话状态不变.<-> G[会话记录页该行<br/>仍为原状态(已结束/已转接…)]
```

> 一句话口径:**会话记录页点「创建工单」→ 跳建单页带会话上下文 → 核对提交 → 工单进列表,历史会话本身不动。**

## 零、改动清单

> **原则**:不新建页面/组件;复用 V0.6 建单页。改动仅 2 个文件。

| 序号 | 动作 | 对象 | 说明 |
|------|------|------|------|
| 0.1 | **加行操作入口** | `admin-session-record.html` | JS 遍历所有 `tbody tr`,在 `.row-actions` 追加「创建工单」链接(统一,所有状态行) |
| 0.2 | **行操作委派** | `admin-session-record.html` | `document click` 委派加「创建工单」分支:读行 data(`.col-id` / `.col-user` / `data-ent` / `data-brand` / `.col-summary .leave-msg`)→ 拼 URL → `location.href` 跳建单页 |
| 0.3 | **改 session 分支** | `admin-ticket-create.html` | session 分支从**写死(陈芳)**改为**从 URL 读真实参数**(sid/name/phone/ent/mall/desc),无参回退演示值 |
| 0.4 | **企业/商城兜底** | `admin-ticket-create.html` | 新增 `applySelectValue`:带入值不在字典选项时追加为 option 再选中(会话记录页"客户A/品牌商城1"口径与工单字典"苏宁邮政/兆点福利"不一致) |
| 0.5 | **补默认值** | `admin-ticket-create.html` | session 模式补:反馈方式=在线客服会话、协助部门=客服部、优先级=一般(受理客服全局已默认当前客服) |
| 0.6 | **不改** | V0.6 列表 / 详情 / 配置 / standalone·order·batch 分支 | session 分支改动不影响其他模式;工单实体/状态机沿用 V0.6 |

> 顺带:0.3 / 0.4 **根治**了原工作台 session 模式"聊李晓红、跳出陈芳"的带入错位根因(session 分支现在统一读 URL 真实数据)。

## 一、范围边界

| 范围 | 内容 |
|------|------|
| **In Scope (本期)** | 会话记录页行操作「创建工单」入口 / 跳建单页 session 模式带会话上下文 / 企业·商城追加选项兜底 / 会话维度默认值 |
| **Out Scope(本期不做)** | 会话记录页**行内工单回写标记**(不像工作台有会话条标记/工单 tab;本入口提交后在建单页提示,会话记录页本身不改,见 §七 Q3) / 进行中会话的实时转单(走工作台抽屉,本入口对进行中也可用但不做实时回写) |

| 代号 | 角色 | 会话记录创建工单职责 |
|------|------|---------------------|

## 二、入口与触发

### 二.1 入口位置

会话记录页(`admin-session-record.html`)表格每行「操作」列(`.row-actions`)追加「创建工单」链接,与"详情 / 再次联系 / 查看评价 / 查看转接 / 分配"并列。由 JS 统一追加(不逐行改 HTML),所有状态行均带。

### 二.2 适用状态

| 状态 | 是否加入口 | 说明 |
|------|:---:|------|
| 已结束 / 已转接 / 已取消 | ✅ 加 | **典型补单场景**(历史会话回顾发现需补工单) |
| 进行中 | ✅ 加 | 进行中会话也可从此入口补单(实时转单另可走工作台抽屉,两条路并存) |
| 离线待处理(留言态) | ❌ 不加 | **未分配客服**,走"分配→接起→(进行中)转工单"正常流程,不跳过接起直接建单 |

### 二.3 触发

点击「创建工单」→ 读该行数据 → 跳:
```
admin-ticket-create.html?mode=session&sid={会话ID}&name={客户}&phone={手机}&ent={企业}&mall={商城}&desc={最后消息}
```

## 三、带入字段定义

### 三.1 从会话记录行带入(行 data → URL 参数 → 建单页 session 分支)

| URL 参数 | 来源(行内) | 落到建单页 | 口径 |
|----------|-----------|-----------|------|
| `sid` | `.col-id` 文本(`#CS…`) | 上下文框"来源会话" + `state.session_id` | 会话 ID |
| `name` | `.col-user` 客户名 | `fContactName`(联系人) + 上下文框"客户" | |
| `phone` | `.col-user` 手机(脱敏 `138****2891`) | `fContactPhone`(移动电话) + 上下文框 | **脱敏**;正式后端建单权限给全号 |
| `ent` | `tr.data-ent`(`客户A`) | `fEnterprise`(企业) + 上下文框 | 口径与字典不同,追加选项兜底(三.3) |
| `mall` | `tr.data-brand`(`品牌商城1`) | `fMall`(商城) + 上下文框 | 同上 |
| `desc` | `.col-summary .leave-msg`(最后消息) | `fDesc`(工单描述) + 上下文框"客户原话" | 最后消息作描述初稿,可改 |

### 三.2 建单页默认值(session 模式,降低填写成本)

| 字段 | 默认值 | 理由 |
|------|--------|------|
| 反馈方式 | **在线客服会话** | 会话转的天然来源 |
| 协助部门 | **客服部** | 默认客服部,跨部门协同再改 |
| 优先级 | **一般** | |
| 受理客服 | 当前登录客服 | 建单页全局已设(原型 `张小明`) |

### 三.3 已知点:企业 / 商城口径差异

会话记录页用"客户A/B/C + 品牌商城1/2/3"占位体系,工单字典(`ticket-dict.js`)用"苏宁邮政 / 东莞邮政 / 昆山吉波 / 宏兆自营 + 兆点福利"。带入值不在字典选项 → `applySelectValue` **追加为 option 再选中**(保证可见),客服可下拉改选规范值。正式接后端、口径统一后自然命中字典选项,兜底可移除。

### 三.4 不带(需客服填)

| 字段 | 必填 | 说明 |
|------|:---:|------|
| 工单业务类型(三级) | 是 | 无法从会话推断,必选 |
| 责任承担方 | 投诉类必填 | 投诉类联动 |
| 关联订单 | 否 | **行内无订单信息**,点「+添加订单」(复用 `drawer-ticket-order.html`)选 |
| 来电电话 / 联系地址 | 否 | 行内无,需售后跟进时填 |
| 完成期限 / 二次投诉 / 新联系人 | 否 | 按需 |

## 四、用例

### UC-SR-01 点击创建工单
- **前置**:会话记录页已加载,列表至少一行。
- **主流程**:任一行「操作」→「创建工单」→ 读行 data 拼 URL → `location.href` 跳建单页。
- **后置**:建单页以 session 模式加载,触发 UC-SR-02。

### UC-SR-02 上下文带入
- 建单页 session 分支读 URL → 顶部「已从会话带入(创建工单)」框显示:客户 / 手机 / 来源会话 / 企业 / 商城 / 客户原话。
- 联系人、移动电话、工单描述、企业、商城预填;反馈方式、协助部门、优先级、受理客服按三.2 默认。
- 企业/商城若不在字典选项,追加 option 选中(三.3)。

### UC-SR-03 核对补充
- 客服选业务类型(必填)、(投诉类)责任承担方、「+添加订单」关联订单、改联系方式/地址等。

### UC-SR-04 提交(创建工单)
- 校验同 V0.6(业务类型/反馈方式/协助部门/受理客服/描述必填,投诉类责任承担方必填)。
- 通过 → 生成 `#TK`(source=1,`session_id`=该历史会话)→ 进 V0.6 工单列表 / 详情,正常受理/跟进/完工。
- **会话记录页该会话状态不变**(仍已结束/已转接/…)。

### UC-SR-05 边界
- 行数据缺某项(如无手机/无最后消息)→ 该 URL 参数不传 → 建单页对应字段空,客服手填。

## 五、业务规则

| 编号 | 规则 |
|------|------|
| **BR-SR-01** | **补单语义**:此处建工单**不改会话状态**;工单与历史会话关联(`session_id`)用于追溯。区别于工作台转工单的"会话继续"(BR-TF-01)。 |
| **BR-SR-02** | **复用建单页**:一页多入口,本入口 = session 模式;不新建页面/组件;建单表单/校验/状态机全沿用 V0.6 §三。 |
| **BR-SR-03** | **来源固定**:`source=1`(会话转),不展示来源选择。 |
| **BR-SR-04** | **工单仅客服可见**:建单/工单均为内部,用户端无感知,不给客户发消息。 |
| **BR-SR-05** | **落库等价**:本入口与工作台转工单产出的工单,在 V0.6 列表/详情等价处理;差异仅入口形态(跳页 vs 抽屉)。 |
| **BR-SR-06** | **数据权限**:遵循 V0.6 §一.1(R-A 见分配给自己的,R-S 见全部);本入口不额外加权限。 |

## 六、与建单页 / V0.6 / 工作台 PRD 衔接

- **建单页 `admin-ticket-create.html`**:本入口复用其 session 分支(V0.6 §0.17);0.3 / 0.4 / 0.5 改动仅作用于 session 分支,**不影响** standalone / order / batch。
- **V0.6**:工单实体 / 字段 / 状态机 / 列表 / 详情全沿用;本入口是其创建入口之一。
- **《工作台转工单-V0.1》**:对照文档。同为会话维度建单,但:
  - 工作台 = **抽屉 + 会话继续**(重交互,进行中会话,边聊边转)
  - 本文 = **跳页 + 补单**(轻入口,历史会话,回顾补建)
  - 两者**互补**:进行中会话去工作台,历史会话来会话记录页。
