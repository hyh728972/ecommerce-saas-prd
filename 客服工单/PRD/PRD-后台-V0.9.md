# PRD-后台-V0.9

> **版本**: V0.9 | **日期**: 2026-07-08 | **状态**: 评审稿
>
> **原型目录**: `prototype-cs/admin/`
>
> **变更摘要（V0.8 → V0.9）**:
> 1. **超时预警重构** — 精简为 3 类预警（首次响应/轮次响应/转接），挂起超时自动回复后进入轮次响应超时；操作统一为「接入会话」；轮次响应超时增加催办；未回复消息按钮统一为「回复」。
> 2. **会话记录增强** — 新增会话类型（人工/机器人）；两次转接人工之间为机器人会话；企业/品牌筛选项合并为多选级联下拉框；详情展示完整聊天记录；时间列改为最后消息时间。
> 3. **会话转接细化** — 原因列仅显示标签；新增备注列；在线客服满载红色、其余蓝色；去除售后组；客服列表去「在线」前缀。
> 4. **自动回复扩展** — 新增催评自动消息（第 6 段）；催评次数改为可配置（默认 1 次）；机器人 FAQ 命中策略去掉「按优先级」。
> 5. **会话规则精简** — 去掉排队等待超时卡片。
> 6. **话术库调整** — 话术关键词拆分为独立列；去掉业务分类列。
> 7. **会话管理角色区分** — 明确主管与客服在筛选项、转接记录上的可见性差异。
> 8. **转接日志事件扩展** — 新增 `transfer.viewed`、`session.type_change` 等事件。

### 一.1 角色列表

| 代号 | 角色 | 说明 |
|------|------|------|
| R-A | 客服 | 工作台接待、待办处理、转接发起、消息撤回/隐藏/脱敏、留言回复（分配后）。A 仅见分配给自己的会话 |
| R-S | 客服主管 | 更高权限：留言分配/回复、知识库上下线、话术管理、会话规则配置、自动回复配置、转接回退策略配置、催办/催评。S 见全部会话 |
| R-C | 终端用户 | 后台各模块的数据产出方（发消息、提留言、提交评价）；本稿仅在与后台交互边界处出现 |
| R-SYS | 系统 | 非人自动：cron 会话超时结束、转接 TTL 回退、WS 推送、敏感词过滤、留言 60s 冷却防重、评价超时归跳过、欢迎语/离线语/催评自动推送、挂起超时自动回复 |

> **审计口径**（ADR-0001）：任一会话/转接/留言状态迁移必须可区分是 R-S（人点）还是 R-SYS（自动）。R-C/R-A/R-S = source 0/1/1，R-SYS = source 2。
>
> **数据可见性**（ADR-0002）：R-A 仅见分配给自己的会话，R-S 见全部。多客服在线时由路由自动分配。
>
> **角色筛选规则（一期）**：
> - **R-A 客服**：会话记录、会话转接 — 无客服/企业/品牌筛选项，仅见与自己相关的会话（`admin_id = 当前客服`）；会话转接列表仅展示 `from_admin_id = 当前客服 OR to_admin_id = 当前客服` 的记录。
> - **R-S 主管**：全量可见，含全部筛选项和全部会话/转接记录。

## 四、数据仪表盘（代号：D）

客服主管运营驾驶舱。统一筛选栏（日期范围 + 客服）驱动 4 指标卡 + 会话量趋势 + 满意度排行 + 待办汇总 + 今日概况。指标卡采用卡片式，主指标在上、子指标在下。

- **入口**: 侧边栏 > 数据仪表盘
- **关键元素**: 统一筛选栏（日期范围选择器默认当日 + 客服下拉默认全部）、时效说明、4 指标卡（各含主指标+子指标）、会话量趋势柱状图、满意度排行、待办汇总、今日概况
- **使用角色**: R-A / R-S

### 六.2 核心流程

#### 六.2.1 超时预警三类阈值

> 会话超时（静默）与排队超时不存在，已移除。挂起超时不需要预警——挂起超时后系统自动回复，然后进入轮次响应超时计时。

| 类型 | 阈值 | 着色 | 触发 | 操作 |
|------|------|------|------|------|
| 首次响应超时 | 5 分钟 | orange 临界 | 用户首条消息后客服未响应 | 接入会话 / 催办 / 转接 |
| 轮次响应超时 | 3 分钟 | orange 临界 | accept 状态下客服未回复用户后续消息 | 接入会话 / 催办 / 转接 |
| 转接超时 | 5 分钟 | orange 临界 | transfer 目标客服超时未接 | 催办 |

> - 阈值与会话规则联动：`first_resp_timeout`(首次响应)/`round_resp_timeout`(轮次响应)/`transfer_timeout`(转接)。
> - 挂起超时 → 系统自动回复消息 → 回复后开始轮次响应超时计时，不再单独产生挂起预警。
> - 转接超时仅支持催办操作，回退策略在会话规则中配置。
> - 回复、接入、立即接入统一为「接入会话」操作。

#### 六.2.2 评价状态流转

```mermaid
stateDiagram-v2
    [*] --> 待评价: 会话结束
    待评价 --> 已评价: 用户提交评价
    待评价 --> 已跳过: 用户主动跳过
    待评价 --> 已过期: 超时未填写(会话规则·评价过期时间)
    已跳过 --> 待评价: 主管手动催评(累计未达催评上限)

    note right of 待评价: 取消的会话不生成评价
    note right of 已跳过: 主动跳过不自动催评，但主管可手动催评
    note right of 已过期: 不可再催评
```

#### 六.2.3 紧急度判定

紧急度（`urgency` = high/low）决定未回复消息列的行着色与排序：

- **紧急**：未回复且命中紧急关键词（退款/退货/投诉/差评/破损/物流异常）
- **一般**：其余

> 一期系统自动判定，客服不可手动标记。类目关键词匹配复用后端规则引擎。**未回复消息仅按紧急度判定，不单独考虑等待时长**；排序按分钟数正序（从小到大）。

### 六.3 数据字段

| 字段 | 类型 | 取值 | 说明 |
|------|------|------|------|
| 紧急度 urgency | enum | high/low（紧急/一般） | 系统按规则自动判定 |
| 评价状态 data-status | enum | pending/done/skipped/expired | 待评价列筛选与四态计数（全部/待评价/已跳过/已过期） |
| 超时类型 | enum | first_resp/round_resp/transfer | 对应三类阈值 |

### 七.2 核心流程

#### 七.2.1 会话类型定义

| 会话类型 | 定义 | 会话ID规则 |
|----------|------|-----------|
| 机器人会话 (robot) | 用户与机器人交互的会话段；两次转接人工之间的会话保存为一段机器人会话 | 独立的 `robot_session_id`，由系统生成 |
| 人工会话 (human) | 客服接入后的会话段 | 会话主ID `session_id` |

> 会话生命周期中，用户可能先与机器人对话，转接人工后为人工会话，再次退回机器人时生成新的机器人会话ID。完整的用户交互链路由多个会话段拼接而成。

会话记录为查询终点页，展示会话全生命周期状态流转：

```mermaid
stateDiagram-v2
    [*] --> 排队中: 用户发起咨询
    排队中 --> 服务中: 客服接入
    排队中 --> 已取消: 用户取消
    排队中 --> 离线待处理: 无在线客服/用户主动选留言
    离线待处理 --> 服务中: 客服上线→正常分配
    服务中 --> 已挂起: 客服挂起
    已挂起 --> 服务中: 恢复到期/用户发消息/手动恢复
    服务中 --> 已结束: 客服结束/超时结束
    已结束 --> [*]
    已取消 --> [*]
```

- **离线待处理**：无在线客服时新会话进入此态，用户消息留作留言内容；用户在线时也可主动选留言进入此态
- **已挂起**：客服挂起后会话进入此态，暂停超时计算；挂起超时则自动回复，然后进入轮次响应超时；恢复到期/用户发消息/手动恢复后回到服务中；挂起期间原客服离线则恢复时重分
- **分配路径**：客服上线后由路由自动分配，或主管手动分配
- **视图模式**：默认「按会话」逐条展示；支持「按用户」归集视图（同用户折叠+展开完整对话流），两视图互斥

### 九.2 核心流程

#### 九.2.1 转接单状态机

```mermaid
stateDiagram-v2
    [*] --> 待处理: 发起转接/重新转接
    待处理 --> 已接受: 目标接受
    待处理 --> 已拒绝: 目标拒绝/满载自动
    待处理 --> 已取消: 源取消/客户取消
    待处理 --> 已超时: TTL到期无响应
    已接受 --> [*]
    已拒绝 --> [*]
    已取消 --> [*]
    已超时 --> [*]: 执行回退策略
```

| 当前状态 | 目标状态 | 触发动作 | 守卫条件 | 执行角色 |
|----------|----------|----------|----------|----------|
| — | pending | 发起/重新转接 | 目标容量 < 上限 | R-A |
| pending | accepted | 目标接受 | 并发乐观锁 | R-A |
| pending | rejected | 目标拒绝/满载自动 | — | R-A / R-SYS |
| pending | cancelled | 源取消/客户取消 | — | R-A / R-C |
| pending | timeout | TTL 到期 | 默认 5 分钟（1~60 可配） | R-SYS |

#### 九.2.2 回退策略（TTL 到期，在会话规则中配置）

| 策略 | 说明 |
|------|------|
| 回退至原客服 | 会话自动归还原客服 |
| 重新排队分配 | 进入排队队列，由路由引擎重分 |
| 自动取消并通知 | 转接取消，原客服+用户均收到通知 |

#### 九.2.3 异常与边界

| 场景 | 处理 |
|------|------|
| 满载目标 | 前端硬阻断（按钮 disabled + 灰字） |
| 连环限深（ADR-0003） | 深度上限 3 跳（原客服 + 最多 2 次主动转接），超限拒绝；每跳独立转接单+独立 TTL |
| 限深计数重置（ADR-0003） | timeout 回退走「重新排队分配」时计数归零（系统兜底重分≠客服踢皮球） |
| 离线宽限（ADR-0003） | 客服离线时名下活跃会话宽限 2 分钟，重连恢复；超时转排队重分 |
| 失败回流（ADR-0003） | rejected/cancelled -> 回源客服恢复可发；timeout -> 走回退 3 选 1 |
| 重新排队次数上限（Q1/ADR-0003） | 累计 2 次仍无人接手 -> 终止兜底：优先回原客服（在线）、否则结束+致歉+留言邀约 |
| 失败回流消息归属（Q4/ADR-0003） | 转接期间进队列的用户消息，失败回流时一并退原客服（作为未读），绝不丢消息 |

#### 九.2.4 转接日志事件

> 每次转接操作的关键节点均记录为事件，用于审计追溯（ADR-0001）和转接质量分析。

| 事件名 | 触发时机 | 操作角色 | 关键字段 |
|--------|----------|----------|----------|
| `transfer.created` | 源客服发起转接 | R-A | transfer_id/session_id/from_admin_id/to_admin_id/reason/remark/depth |
| `transfer.viewed` | 目标客服首次查看转接请求 | R-A | transfer_id/viewed_at |
| `transfer.accepted` | 目标客服接受 | R-A | transfer_id/accepted_at |
| `transfer.rejected` | 目标拒绝/满载自动 | R-A / R-SYS | transfer_id/rejected_at（满载时 reason=capacity） |
| `transfer.cancelled` | 源/客户取消 | R-A / R-C | transfer_id/cancelled_at/cancel_by |
| `transfer.timeout` | TTL 到期 | R-SYS | transfer_id/timed_out_at |
| `transfer.rollback` | 回退策略执行 | R-SYS | transfer_id/strategy（回退原客服/重新排队/自动取消） |
| `transfer.reminder` | 催办通知 | R-A / R-S | transfer_id/reminded_by |
| `session.type_change` | 会话类型变更（机器人↔人工） | R-SYS | session_id/from_type/to_type/reason |

> **V0.9 新增事件建议**：
> - `transfer.viewed`：目标客服首次查看转接请求时记录，用于衡量转接响应效率。
> - `session.type_change`：会话在机器人与人工之间切换时记录，配合新增的会话类型（robot/human）概念，用于追踪完整用户交互链路中的人工接管节点。
>
> **公共字段**：`event_id`（PK）/ `event_type` / `transfer_id`（FK，转接类事件）/ `session_id`（FK） / `operator_id` / `operator_type`（1=R-A / 2=R-SYS，满足 ADR-0001 审计口径） / `created_at` / `metadata`（json，存 reason/remark/strategy 等附加上下文）。
>
> 落表建议：新建 `customer_chat_transfer_events`（事件流水表），与 `customer_chat_transfers`（转接单主表）1:N 关联；`session.type_change` 事件可复用该表或独立建 `customer_chat_session_events`。

### 九.3 数据字段

| 字段 | 取值 | 说明 |
|------|------|------|

## 十八、实时通信

### 十八.1 连接协议

| 项 | 说明 |
|----|------|
| 协议 | WebSocket（ws/wss） |
| 鉴权 | 供应链系统网关统一鉴权 |
| 心跳 | ping/pong 保活，超时断开重连 |
| 断线补偿 | 重连上报 `last_message_id`，后端推该 ID 之后缺失消息 |

### 十八.2 Action 协议

| Action | 方向 | 触发 | 说明 |
|--------|------|------|------|
| send-message / receive-message | 双向 / S→C | 收发消息 | 用户/客服发消息 |
| receipt | S→C | 发送回执 | message_id + timestamp |
| read | 双向 | 已读 | 更新 is_read |
| user-online / user-offline | S→C | 用户上下线 | 通知客服端 |
| waiting-users / waiting-user-count | S→C | 队列变化 | 等待列表/计数 |
| admins | S→C | 客服列表 | 用户端展示在线客服 |
| user-transfer | S→C | 转接 | 通知目标客服 |
| error-message | S→C | 错误 | 推送错误 |

> 消息类型：text / image / audio / video / pdf / navigator / rate / notice（+ 富媒体：order_card / product_card / coupon_card / cart_card / logistic_card / refund_card）。
> 消息来源：0=用户 / 1=客服 / 2=系统（AI=3 属 3 期）。
