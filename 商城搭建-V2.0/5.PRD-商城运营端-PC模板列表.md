## 0. 文档范围

本文档只覆盖商城运营工作台中 **「PC模板列表」** 这一功能模块（顶部第二个 Tab），描述其与「模板列表」（移动端模板）的差异、自身的列表/筛选/批量/单条操作/分页/空状态等完整行为。

涉及推送品牌商城、应用列表、新建应用、推送详情等其它模块，仅在需要明确边界时简述，详见各自 PRD。

## 1. 产品概述

### 1.1 需求背景

商城搭建系统已支持「移动端模板」的搭建与发布。随着品牌方在 PC 端的运营投入加大（旗舰店首页、品类频道页、活动会场页等），运营团队需要独立维护 **PC 端模板库**：

- PC 页面布局与移动端差异大（横版 Banner、楼层多列、PC 头部等），不能直接复用移动端模板；
- 需要按"美妆 / 食品 / 服饰 / 大促"等业务标签分类管理；
- 需要支持草稿 / 已发布两种状态流转；
- 需要支持批量打标签、单条编辑、发布、删除等日常运营操作。

因此新增「PC模板列表」Tab，与「模板列表」（移动端）并列。

### 1.2 产品目标

| 目标 | 衡量指标 |
|---|---|
| PC 模板与移动端模板解耦管理 | PC 模板独立列表、独立数据源、独立封面预览 |
| 运营自助完成日常操作 | 单条增删改查 + 批量打标签 全部覆盖 |
| 列表浏览效率 | 5 条/页卡片瀑布，支持名称/状态/标签三维筛选 |
| 与编辑器无缝衔接 | 卡片"编辑"直接跳转 `editor.html` |

### 1.3 目标用户

| 角色 | 主要场景 |
|---|---|
| 平台运营 | 维护 PC 端模板库（美妆、食品、服饰、大促等场景） |
| 运营管理员 | 批量调整标签、清理无效模板 |
| 品牌方 | 间接消费：通过后续推送流程接收到 PC 模板（当前原型未启用） |

### 1.4 名词解释

| 术语 | 含义 |
|---|---|
| PC 模板 | PC 端商城页面模板，宽度按 PC 浏览器（≥ 1200px）设计 |
| 移动端模板 | 移动 H5 商城页面模板，「模板列表」Tab 管理 |
| 标签 | 模板的业务分类标签，用于筛选与排序（美妆 / 食品 / 服饰 / 618大促 …） |
| 草稿（draft） | 编辑中、不可被消费的模板状态 |
| 已发布（published / pushed） | 已对外发布，可被引用；`pushed` 是已推送过的子集，UI 上统一显示"已发布" |
| 使用次数（useCount） | 模板已被引用/推送的次数；UI 不展示，但用作删除二次确认的依据 |

## 3. 数据模型

### 3.1 PC 模板对象

数据源：`MOCK_PC_TEMPLATES`（生产环境替换为后端接口）。

```ts
type PcTemplate = {
  id: string;          // 主键，如 'pc1'
  name: string;        // 模板名称
  status: 'draft'
       | 'published'   // 已发布
       | 'pushed';     // 已发布且已推送过（UI 显示同"已发布"）
  tags: string[];      // 业务标签，如 ['美妆', '618大促']
  updatedAt: string;   // 最近修改时间，格式 'YYYY-MM-DD HH:mm'
  useCount: number;    // 被引用/推送次数（卡片不展示，删除校验用）
};
```

| id | 名称 | 状态 | 标签 | 使用次数 |
|---|---|---|---|---|
| pc1 | PC 美妆旗舰首页 | published | 美妆 | 8 |
| pc2 | PC 食品生鲜频道 | draft | 食品 | 0 |
| pc3 | PC 服饰大促会场 | pushed | 服饰、618大促 | 14 |
| pc4 | PC 通用品牌馆 | published | 美妆、服饰 | 5 |
| pc5 | PC 会员日活动页 | draft | 美妆 | 0 |
| pc6 | PC 618 主会场 | pushed | 618大促 | 22 |

### 3.3 状态显示映射

| 原始 status | UI 文案 | 颜色 class |
|---|---|---|
| `draft` | 草稿 | `status-draft` |
| `published` | 已发布 | `status-published` |
| `pushed` | 已发布 | `status-published` |

## 4. 列表渲染

### 4.1 卡片结构

每张 PC 模板卡片（`article.template-card.template-card--pc`）结构：

```
┌─────────────────────────────────────┐
│  封面区（template-card-cover）       │
│  ─ 横版 PC 预览图（640×360 SVG）     │
│  ─ 左上：勾选框                      │
│  ─ 右上：状态标签                    │
│  ─ 悬停：预览按钮（遮罩）            │
├─────────────────────────────────────┤
│  正文（template-card-body）          │
│  ─ 模板名称（无"使用 N 次"角标）     │
│  ─ 标签 chips（无标签时显示"未设置"）│
│  ─ 最近修改：YYYY-MM-DD HH:mm        │
│  ─ 操作按钮：[编辑] [发布?] [删除]   │
└─────────────────────────────────────┘
```

### 4.2 与移动端模板卡片的差异

| 维度 | PC 模板 | 移动端模板 |
|---|---|---|
| 卡片 class | 多 `template-card--pc` | `template-card` |
| 封面 SVG | `getPcTemplatePreviewSrc`（640×360 横版） | `getTemplatePreviewSrc`（640×400 含 4 个入口卡） |
| 标题右侧 | 无 | "使用 N 次" 角标 |
| 行内 checkbox class | `row-check-pc` | `row-check` |
| 全选 checkbox id | `check-all-pc` | `check-all` |
| 选中数摘要 id | `pc-template-selection-summary` | `template-selection-summary` |
| 容器 id | `pc-template-tbody` | `template-tbody` |
| 分页容器 id | `pc-template-pagination` | `template-pagination` |
| 行内按钮 class | `btn-pc-edit / btn-pc-publish / btn-pc-delete / btn-pc-preview` | `btn-edit / btn-publish / btn-delete / btn-preview` |

### 4.3 PC 封面预览图（自动生成）

`getPcTemplatePreviewSrc(t)` 按模板标签自动选择 4 套调色板生成 SVG：

| 命中标签 | 调色板 | 主色 |
|---|---|---|
| 美妆 | beauty | `#FF6B6B → #FF9F7F` + `#FFF1F0` |
| 食品 | food | `#52C41A → #95DE64` + `#F6FFED` |
| 服饰 | fashion | `#722ED1 → #B37FEB` + `#F9F0FF` |
| 618大促 / 默认 | promo | `#1677FF → #69B1FF` + `#E6F4FF` |

> 命中优先级按代码顺序：`美妆 → 食品 → 服饰 → 618大促`（后命中会覆盖前面的 palette，因此 618大促 实际会覆盖前面任一标签）。生产化后建议改成"按主标签"或允许多色调手工指定。

SVG 内容包含：白色顶栏 + 红色搜索按钮 + 一条 Banner 渐变带 + 标题/副标题占位 + 3 个并列内容卡。最终以 `data:image/svg+xml;charset=UTF-8,<encodeURIComponent>` 形式内联到 `<img src>`。

### 4.4 标签显示

- 模板有标签：按 `tags` 数组顺序渲染 `<span>tag</span>` chips；
- 模板无标签：渲染单个 `<span>未设置标签</span>` 占位。

### 4.5 分页

| 字段 | 取值 |
|---|---|
| 每页条数 | 5（与移动端共用 `TEMPLATE_PAGE_SIZE`） |
| 显示元素 | `共 N 条` + `上一页` + 数字页码 + `下一页` |
| 边界处理 | 当前页为第 1 页时禁用"上一页"；为最后一页时禁用"下一页" |
| 越界回退 | 若 `currentPcTemplatePage > totalPages`，自动回退到 `totalPages` |
| 翻页交互 | 点击页码按钮 → 更新 `currentPcTemplatePage` → 重渲染列表与分页 |

### 4.6 空状态

筛选/搜索结果为空时：

- 容器内显示 `<div class="template-empty">暂无符合条件的 PC 模板</div>`；
- `selectedPcTemplateIds` 清空；
- 全选框 `check-all-pc` 的 `checked=false`、`indeterminate=false`；
- 已选摘要归零；
- 分页区域清空（不渲染任何按钮）。

## 5. 选择与批量操作

### 5.1 单条勾选

- 每张卡片左上角 checkbox，class `row-check-pc`；
- 任何勾选变化触发 `onPcRowCheckChange`：
  - 重新计算 `selectedPcTemplateIds`；
  - 同步顶部全选框状态：`checked`（全选）/ `indeterminate`（部分选）/ 都不选（空）；
  - 更新顶部"已选择 N 个模板"摘要。

### 5.2 全选当前页

- 顶部「☑ 全选当前页」(`#check-all-pc`)：
  - 勾选 → 当前页所有可见卡片勾选；
  - 取消 → 当前页所有可见卡片取消勾选；
- 仅作用于"当前页"，跨页选择不影响其它页已选项（注意：本原型实现中，翻页会重新渲染，已勾选状态依赖 `selectedPcTemplateIds` 数组内存保留）。

### 5.3 批量设置标签

入口：筛选区右侧「批量设置标签」按钮（与移动端模板共用）。

- 触发前校验：当前 Tab 已选模板数 = 0 时 `alert("请先勾选要操作的模板。")`，弹窗不打开。
- 弹窗内：
  - 标题显示"批量设置标签"；
  - 副标题显示"已选 N 个模板"；
  - 标签编辑区初始展示所选模板标签的**并集** chips；
  - 提示文案：
    > 以下为所选模板标签的并集；点击 × 删除标签，或在输入框中输入后按回车 / 逗号 添加。点击「应用」将同步到所有已选模板（相对打开弹窗时的列表：少掉的视为删除，多出的视为新增）
  - 输入框支持回车 / 中英文逗号 添加标签。
- 应用时差量计算：
  - `removedTotal` = 打开弹窗时的并集 − 应用时的列表（视为删除）
  - `addedTotal` = 应用时的列表 − 打开弹窗时的并集（视为新增）
  - 未检测到变更 → `alert("未检测到变更，请删除或添加标签后再应用。")`
- 应用后提示：`演示：已对 N 个模板更新标签。累计移除 X 处标签。累计新增 Y 处标签。`
- 关闭弹窗 → `applyFiltersAndRender()` 重渲染（PC 与移动端列表同时刷新）。

> **注意**：批量标签操作以"当前 Tab 已选模板"为作用域 —— 在 PC 模板 Tab 下点击「批量设置标签」时，只影响 PC 模板；在移动端模板 Tab 下点击时，只影响移动端模板。

## 6. 行内操作

每张卡片底部固定的操作按钮区（与移动端模板对齐，**不含**"推送品牌商城"按钮）。

### 6.1 编辑

- 按钮：`[编辑]`，class `btn-pc-edit`，恒显示；
- 行为：`openEditor(id)` → 新窗口打开 `editor.html?id=<id>&name=<name>`（1200×800，可滚动）；
- 名称解析：先在 `MOCK_TEMPLATES` 查找 → 再到 `MOCK_PC_TEMPLATES` 查找 → 都找不到则用 id 占位。

### 6.2 发布

- 按钮：`[发布]`，class `btn-pc-publish`，**仅当 `status === 'draft'` 时显示**；
- 行为：`openPublishPreview(id)` → 弹出"发布前预览"对话框：
  - 顶部提示："请确认模板在 PC 与移动端预览无误后再发布。"
  - 预览设备 Tab：仅显示「移动端预览」（PC 预览 Tab 在代码中已被注释，预留位）
  - 预览区域：占位框（演示）
  - 底部按钮：`[返回编辑]` / `[确认发布]`
- 确认发布：`alert("演示：模板已发布。实际会更新状态为「已发布」并记录审计日志。")`，关闭弹窗，调用 `applyFiltersAndRender` 刷新。

### 6.3 删除

- 按钮：`[删除]`，class `btn-pc-delete`，红色（`btn-danger`），恒显示；
- 行为：`onDeletePcTemplate(id)`
  - 若 `status === 'pushed'` 且 `useCount > 0`：弹出二次确认 `confirm("该 PC 模板已推送给 N 个品牌，删除后品牌方将无法使用。是否确认删除？")`；取消则中止；
  - 弹出 `alert("演示：已删除 PC 模板「name」。")`（实际可为软删并通知下游）；
  - 调用 `applyFiltersAndRender` 刷新。

### 6.4 预览（封面悬停）

- 卡片封面悬停显示遮罩 + 眼睛图标的「预览」按钮（class `btn-pc-preview`）；
- 当前实现：`alert("演示：预览 PC 模板「name」，实际可在新窗口打开预览 URL。")`；
- 生产化建议：新窗口打开 `<previewUrl>?id=<id>&device=pc`。

## 7. 新建 PC 模板

### 7.1 入口

页头「+ 新建模板」按钮 → 弹出"新建模板"对话框。

### 7.2 弹窗字段

| 字段 | 控件 | 默认 | 说明 |
|---|---|---|---|
| 创建方式 | 单选 | 从空白新建 | 从空白新建 / 复制已有模板 |

| 模板名称 | 文本 | 空 | 必填，留空回退为"未命名模板" |

### 7.3 确认行为

- 复制：`alert("演示：将复制模板 <srcId> 并进入编辑。\n新建模板名称：<name>")`；
- 空白：`alert("演示：从空白创建模板「<name>」并进入编辑器。")`；
- 关闭弹窗 → `openEditor('new')`（新窗口打开 `editor.html?id=new&name=...`）。

> 当前原型不在 mock 列表中真正插入新模板，仅演示流程；生产化时应在确认后调用后端创建接口，成功后回到列表并定位到新模板。

## 8. 与"推送品牌商城"的边界

当前「推送品牌商城」弹窗（`openPushModal`）的模板下拉来源 **仅** `MOCK_TEMPLATES`（移动端模板），并过滤 `status === 'published' || 'pushed'`。

> **PC 模板暂不参与"推送品牌商城"流程**。若产品后续需要把 PC 模板也推送给品牌方，需要：
> 1. `openPushModal` 的下拉源扩展为「移动端 + PC」两类，或新增 Tab；
> 2. `confirmPush` 上送时携带 `templateType: 'mobile' | 'pc'`；
> 3. 后端推送任务支持 PC 模板类型。

## 9. 交互流程图

### 9.1 浏览 / 筛选

```
进入「PC模板列表」Tab
  → applyFiltersAndRender
  → 读取 MOCK_PC_TEMPLATES，按 名称/状态/标签 过滤
  → 写入 filteredPcTemplates，页码重置为 1
  → renderPcTemplatePage → renderPcTemplateList + renderPcTemplatePagination
```

### 9.2 批量打标签

```
勾选若干卡片
  → 点击「批量设置标签」
  → 校验已选数量 > 0
  → 弹窗：回填所选模板标签并集
  → 输入/删除标签
  → 点击「应用」
  → 差量计算（removed/added）
  → 写回 MOCK_PC_TEMPLATES 中所选模板的 tags
  → applyFiltersAndRender 重渲染
```

### 9.3 单条发布

```
点击卡片「发布」(仅 draft 显示)
  → 打开发布前预览弹窗
  → 切换预览设备（当前仅移动端 Tab）
  → 点击「确认发布」
  → alert 提示 + 关闭弹窗 + 重渲染
```

### 9.4 单条删除

```
点击卡片「删除」
  → 若 pushed 且 useCount > 0：confirm 二次确认
  → alert 提示 + 重渲染
```
